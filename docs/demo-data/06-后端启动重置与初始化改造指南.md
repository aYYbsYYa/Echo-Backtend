# 后端启动重置与初始化演示数据改造指南

## 1. 目标行为

后端每次真正启动服务时执行以下流程：

1. 清空所有业务 JSON 集合。
2. 清理演示期间上传的图片文件。
3. 按固定 ID 写入本目录定义的演示数据。
4. 根据当前启动时间动态生成内容时间和胶囊状态。
5. 完成关联完整性检查。
6. 再开始接受 HTTP 请求。

重启后的状态必须完全可重复。演示期间新增的用户、内容、点赞、留言和胶囊会在下一次重启后消失。

## 2. 当前项目现状

当前入口为 `main.py`：模块导入时调用 `create_app()`。`create_app()` 中只调用 `Config.ensure_data_files()`，它只创建不存在的 JSON 文件，不会清空已有内容。

普通业务集合由 `Config.JSON_FILES` 管理，但当前遗漏了灵笺的三个集合：

- `echo_conversations`
- `echo_messages`
- `echo_profiles`

图片还分散在：

- `data/uploads/`：浮笺和飞笺图片。
- `data/capsule_images/`：时间胶囊图片。

因此不能只重置 `Config.JSON_FILES` 中现有的九个文件。

## 3. 推荐目录结构

实现时新增以下代码文件和 Seed 数据目录：

```text
Echo-Backtend/
  app/
    demo_seed/
      __init__.py
      seed_data.py
      seed_runner.py
      assets/
        capsule_sunset.webp   # 可选
```

职责：

- `seed_data.py`：以 Python 结构保存固定文本和关系，提供 `build_demo_data(now)`。
- `seed_runner.py`：负责清空、写入、复制资源和校验。
- `__init__.py`：只导出 `reset_and_seed_demo_data`。

建议使用 Python 数据结构，而不是把本目录 Markdown 当作运行时数据源。Markdown 是内容规格，Python 才是可执行 Seed；不要在启动时解析表格或代码块。

## 4. 配置开关

在 `Config` 中增加：

```python
DEMO_RESET_ON_START = os.getenv("DEMO_RESET_ON_START", "false").lower() == "true"
```

`.env` 演示环境设置：

```dotenv
DEMO_RESET_ON_START=true
```

即使当前需求是“每次重启都清空”，仍建议保留开关。原因是该操作会无条件删除数据，开发者误启动或未来部署时不能默认开启。

同时把完整 JSON 集合更新为：

## 5. Seed 数据构建

`seed_data.py` 提供单一入口：

```python
from datetime import datetime, timedelta, timezone


def build_demo_data(now: datetime | None = None) -> dict[str, list[dict]]:
    now = now or datetime.now(timezone.utc)

    def iso(delta: timedelta) -> str:
        return (now + delta).isoformat()

    return {
        "users": [...],
        "bottles": [...],
        "planes": [...],
        "comments": [...],
        "likes": [...],
        "capsules": [
            {
                "id": "demo_capsule_soon",
                "content": "十秒之后，希望你仍记得：等待本身也是产品体验的一部分。",
                "user_id": "demo_user_main",
                "mood": "calm",
                "duration": "custom",
                "custom_seconds": 60,
                "has_image": False,
                "created_at": iso(timedelta(seconds=-50)),
                "unlock_at": iso(timedelta(seconds=10)),
                "opened_at": None,
            }
        ],
        "echo_conversations": [...],
        "echo_messages": [...],
        "echo_profiles": [...],
        "agent_profiles": [...],
        "agent_matches": [...],
        "agent_dialogues": [...],
    }
```

关键要求：

- 默认参数不能写成 `datetime.now(...)`，否则时间会在模块导入时固定。
- 全部时间使用 timezone-aware UTC datetime。
- 固定关联 ID，不调用 `new_id()` 或 `secrets`。
- `region` 应直接复制作者数据，匹配当前 API 的记录格式。
- 内容池的 `reply` 在 Seed 中写固定文案，不调用外部 AI。

## 6. 清空与写入

`seed_runner.py` 推荐结构：

```python
import shutil
from pathlib import Path

from app.config import Config
from app.storage.json_repository import JsonRepository
from .seed_data import build_demo_data


def _clear_directory(path: Path) -> None:
    if not path.exists():
        return
    for child in path.iterdir():
        if child.is_dir():
            shutil.rmtree(child)
        else:
            child.unlink()


def reset_and_seed_demo_data() -> None:
    data = build_demo_data()

    missing = set(Config.JSON_FILES) - set(data)
    extra = set(data) - set(Config.JSON_FILES)
    if missing or extra:
        raise RuntimeError(f"Seed 集合不一致: missing={missing}, extra={extra}")

    Config.DATA_DIR.mkdir(parents=True, exist_ok=True)
    for name in Config.JSON_FILES:
        JsonRepository(Config.DATA_DIR / f"{name}.json").replace_all(data[name])

    _clear_directory(Config.UPLOAD_DIR)
    _clear_directory(Config.DATA_DIR / "capsule_images")
```

这里先完整构建并校验内存数据，再写入磁盘，避免构建中途报错后只清空了一半。

如加入固定图片，清理完成后再把 `assets` 中的文件复制到目标目录。

## 7. 关联完整性校验

在写入前执行最少以下检查：

```python
def validate_demo_data(data: dict[str, list[dict]]) -> None:
    user_ids = {item["id"] for item in data["users"]}
    bottle_ids = {item["id"] for item in data["bottles"]}
    plane_ids = {item["id"] for item in data["planes"]}
    content_ids = bottle_ids | plane_ids

    assert len(user_ids) == len(data["users"])
    assert all(item["user_id"] in user_ids for item in data["bottles"])
    assert all(item["user_id"] in user_ids for item in data["planes"])
    assert all(item["user_id"] in user_ids for item in data["capsules"])
    assert all(item["item_id"] in content_ids for item in data["likes"])
    assert all(item["item_id"] in content_ids for item in data["comments"])
    assert all(item["user_id"] in user_ids for item in data["likes"])
    assert all(item["user_id"] in user_ids for item in data["comments"])
```

还应检查：

- 每个集合 ID 唯一。
- 同一 `(item_id, user_id)` 只存在一条点赞。
- 内容作者不能为自己的内容点赞。
- 评论 `nickname` 必须等于关联用户的 `nickname`。
- 胶囊 `unlock_at >= created_at`。
- `opened_at` 只能出现在已到期胶囊上。
- `echo_conversations.user_id` 和 `echo_profiles.user_id` 必须存在于 `users`。
- 每条灵笺消息的 `conversation_id` 必须存在，画像用户和会话用户必须一致。
- Agent profile、match、dialogue 及 `conversation[].user_id` 必须存在于 Soul Agent Demo 用户集合。

不要用 Python `assert` 作为最终生产校验，因为优化模式可能移除断言；实现时应改成显式条件并抛出 `ValueError` 或 `RuntimeError`。上面代码仅表达检查内容。

## 8. 接入应用启动

在 `create_app()` 中，数据文件准备完成后、注册蓝图前执行：

```python
Config.ensure_data_files()

if Config.DEMO_RESET_ON_START:
    from .demo_seed import reset_and_seed_demo_data

    reset_and_seed_demo_data()
```

放在蓝图注册前便于理解启动顺序，也保证请求到达前数据已经完成初始化。

## 9. Flask Debug 重载器风险

当前 `main.py` 使用：

```python
app.run(..., debug=app.config["DEBUG"])
```

Flask debug reloader 可能启动父、子两个进程，使 `create_app()` 执行两次。结果是：

1. Seed 被执行两次。
2. 第一次进程和第二次进程之间产生的数据会被再次覆盖。
3. 日志中出现两次初始化提示。

演示环境推荐直接关闭重载器：

```python
app.run(
    host="0.0.0.0",
    port=app.config["PORT"],
    debug=app.config["DEBUG"],
    use_reloader=False,
)
```

如果开发时必须使用 reloader，则只在实际服务子进程执行：

```python
import os

should_seed = not app.config["DEBUG"] or os.environ.get("WERKZEUG_RUN_MAIN") == "true"
if Config.DEMO_RESET_ON_START and should_seed:
    reset_and_seed_demo_data()
```

两种方案中，评委演示优先选择 `use_reloader=False`，行为最清楚。

## 10. 不建议使用 `before_request`

不要在 `@app.before_request` 中重置数据。它会在每次请求前清库，导致用户刚发布的内容在下一个请求时消失，也会让点赞和开启胶囊无法完成。

重置只能发生在进程启动阶段。

## 11. 测试方案

至少增加以下测试：

### 重复执行测试

连续调用两次 `reset_and_seed_demo_data()`，确认：

- 各集合数量相同。
- 各集合 ID 相同。
- 不产生重复数据。
- 动态时间围绕第二次执行时间重新计算。

### API 冒烟测试

1. `GET /api/users/demo_user_main` 返回 200。
2. `GET /api/bottles/mine/demo_user_main` 返回两条主身份浮笺。
3. `GET /api/planes/mine/demo_user_main` 返回两条主身份飞笺。
4. `GET /api/capsules/mine/demo_user_main` 同时包含 opened、unlockable、locked 状态。
5. `GET /api/bottles/discover?user_id=demo_user_main` 不返回主身份自己的内容。
6. 主身份能看到自己内容的 `likes`、`comments`、`reply`。
7. 其他身份不能看到作者私有留言和开发组回信。
8. 灵笺画像接口直接返回可用画像。

### 清理测试

先写入一条临时记录和一个临时上传文件，执行重置后确认两者均消失。

测试必须使用临时 `DATA_DIR`，不能清理开发者真实的 `data/` 目录。

## 12. 启动日志

初始化完成后输出一条简洁日志：

```text
[demo-seed] reset complete: users=10 bottles=10 planes=10 capsules=4
```

不要逐条打印用户内容，避免日志冗长。

## 13. 实施顺序

1. 扩充 `Config.JSON_FILES` 并增加环境开关。
2. 建立 `app/demo_seed/seed_data.py`，转录本目录的数据规格。
3. 实现数据校验。
4. 实现 JSON 和图片目录重置。
5. 接入 `create_app()`。
6. 关闭演示环境的 debug reloader。
7. 增加重复执行、API 和清理测试。
8. 将前端本地身份切换到 `demo_user_main`，完整走一遍演示流程。

## 14. 数据安全说明

这是破坏性功能。必须遵守：

- 默认 `DEMO_RESET_ON_START=false`。
- 只在明确的演示环境开启。
- 生产部署禁止开启。
- 不要把真实用户数据放进演示环境的数据目录。
- 启动日志应明确提示重置已发生。
