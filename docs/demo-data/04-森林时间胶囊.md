# 森林时间胶囊

## 1. 设计目标

主身份 `demo_user_main` 启动后同时拥有四种状态，避免演示完全依赖现场等待：

1. 已经开启过的旧信。
2. 已到期但尚未开启的信。
3. 长期锁定的未来信。
4. 启动后约十秒到期的即时演示信。

现场还可以通过前端新建一封 1 分钟胶囊，展示完整创建流程。

## 2. 已开启的旧信

```json
{
  "id": "demo_capsule_opened",
  "content": "我很害怕毕业，觉得没有明确方向就是失败。现在虽然还是没有完全想清楚，但至少已经知道，方向不是一次决定出来的。",
  "user_id": "demo_user_main",
  "mood": "lost",
  "duration": "month12",
  "custom_seconds": null,
  "has_image": false,
  "created_at": "now - 365 天",
  "unlock_at": "now - 2 天",
  "opened_at": "now - 1 天"
}
```

演示作用：列表中可以直接看到内容，并展示等待后的回望。

## 3. 已到期、待开启的信

```json
{
  "id": "demo_capsule_unlockable",
  "content": "如果你打开了这封信，希望你还记得离开学校那天的晚霞。那时你不知道会去哪里，但还是认真地和过去告别了。",
  "user_id": "demo_user_main",
  "mood": "miss",
  "duration": "month1",
  "custom_seconds": null,
  "has_image": false,
  "created_at": "now - 30 天",
  "unlock_at": "now - 5 分钟",
  "opened_at": null
}
```

演示作用：进入森林后立即出现可开启状态，点击后由 API 写入真实的 `opened_at`。

## 4. 长期锁定的信

```json
{
  "id": "demo_capsule_locked",
  "content": "写给一年后的我：希望你没有因为走得慢，就否定这一年的努力。也希望你仍然愿意做一些温暖、真实、暂时看不到回报的事情。",
  "user_id": "demo_user_main",
  "mood": "expect",
  "duration": "month12",
  "custom_seconds": null,
  "has_image": false,
  "created_at": "now - 2 天",
  "unlock_at": "now + 363 天",
  "opened_at": null
}
```

演示作用：证明内容在时间到达前不会由列表接口下发，体现“反即时反馈”。

## 5. 即将到期的演示信

```json
{
  "id": "demo_capsule_soon",
  "content": "60秒之后，希望你仍记得：等待本身也是产品体验的一部分。",
  "user_id": "demo_user_main",
  "mood": "calm",
  "duration": "custom",
  "custom_seconds": 60,
  "has_image": false,
  "created_at": "now - 50 秒",
  "unlock_at": "now + 10 秒",
  "opened_at": null
}
```

注意：后端目前要求自定义总时长至少 60 秒，所以 `custom_seconds` 应写 60；通过让 `created_at` 位于 50 秒前，使它在启动后约 10 秒到期。

## 6. 配图策略

第一版 Seed 建议全部使用：

```json
"has_image": false
```

原因：胶囊图片不是 JSON 内嵌字段，而是以 `data/capsule_images/<capsule_id>.<ext>` 文件存储。只把 `has_image` 写成 `true` 而没有对应文件，会导致图片接口返回 404。

如果后续需要演示配图，应增加一个固定资源，例如：

```text
app/demo_seed/assets/capsule_sunset.webp
```

初始化时复制为：

```text
data/capsule_images/demo_capsule_unlockable.webp
```

并将该记录的 `has_image` 设置为 `true`。

## 7. 接入 Seed 后每次重启的行为

完成启动重置功能后，每次启动会重新 Seed：

- `demo_capsule_unlockable` 会恢复为未开启。
- `demo_capsule_soon` 会重新获得约 10 秒倒计时。
- 现场新建的一分钟胶囊会在下次重启时被清除。
- 已开启旧信始终保持已开启状态，但时间会相对当前启动时间平移。

这正是评委演示所需的可重复状态。
